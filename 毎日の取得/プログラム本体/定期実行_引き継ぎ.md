## 業務目的

日次での案件作成に使うため、各ATS・求人媒体に掲載されている求人情報を定期的に取得します。

取得対象は主に以下です。

- HRMOS
- HERP
- リクナビ
- Talentio
- JobCan

取得したデータはCSVとして保存し、後続の案件作成、確認、集計、共有、加工に利用します。

## 頻度・ボリューム

頻度は平日ベースの定期実行です。

| 曜日 | 実行対象 |
| --- | --- |
| 平日毎日 | HRMOS |
| 月曜 | HERP、リクナビ |
| 火曜 | Talentio |
| 水曜 | JobCan |
| 木曜 | Talentio |
| 金曜 | JobCan |

カテゴリは基本的に以下の5カテゴリです。

- WEB
- IN_DS
- CRS
- CRG
- コンサル

リクナビ、HERP、ATS系はいずれもカテゴリ別にCSVが出力されます。

所要時間は媒体や求人件数により変動します。HERPとリクナビは多数のURL・カテゴリを巡回するため長めです。HRMOS、Talentio、JobCanも5カテゴリ分ログインして処理します。

## スケジュールのルール

平日は毎日HRMOSを実行します。

曜日別に以下を追加実行します。

- 月曜: HERP、リクナビ
- 火曜: Talentio
- 水曜: JobCan
- 木曜: Talentio
- 金曜: JobCan

## 期日感

各実行日のうちに、対象日付のCSVが生成されていれば完了です。

朝や日中の確認・利用に間に合わせる運用の場合、深夜から早朝に自動実行されている想定です。

ファイル名に実行日が入るため、対象日付のCSVが生成されているかを確認します。

例:

```text
output/hrmos/hrmos_WEB_item_list_2026-05-29.csv
output/rikunabi/rikunabi_WEB_item_list_20260525.csv
herp/output_herp_jobs/herp-WEB-20260525.csv
```

## 作業の完了状態・条件

作業完了の条件は、対象媒体・対象カテゴリ分のCSVが生成されていることです。

確認ポイント:

- 当日または対象日のファイル名でCSVが作成されている
- ファイルサイズが極端に小さくない
- ヘッダーだけでなくデータ行が入っている
- 実行ログに致命的なエラーがない

主な出力先:

```text
/Users/ryuga.uchiyama/git/ats-crawling/output/hrmos/
/Users/ryuga.uchiyama/git/ats-crawling/output/talentio/
/Users/ryuga.uchiyama/git/ats-crawling/output/jobcan/
/Users/ryuga.uchiyama/git/ats-crawling/output/rikunabi/
/Users/ryuga.uchiyama/git/ats-crawling/herp/output_herp_jobs/
```

`ats-processors/output/` 側にも出力履歴があります。確認時は、実際に当日ファイルが生成されている場所を優先して見ます。

## イレギュラー時の対応

主なイレギュラー:

- CSVが生成されない
- CSVが空、またはヘッダーしかない
- ログインに失敗する
- サイト側のメンテナンス画面やモーダルで止まる
- タイムアウトする
- サイト側の画面構造変更で取得できない

対応順:

1. 該当日の出力CSVがあるか確認する
2. ログがあればエラー内容を確認する
3. 同じコマンドを手動で再実行する
4. ログイン情報や権限が変わっていないか確認する
5. サイト側の画面変更が疑われる場合はエンジニアに相談する

リクナビはブラウザ操作に依存しているため、メンテナンスモーダルや画面構造変更で失敗しやすいです。

HERPはURL一覧を巡回するため、特定URLが無効になっていても他のURLは続行される設計です。
