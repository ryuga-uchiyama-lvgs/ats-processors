## 業務目的

日次での案件作成に使うため、各ATS・求人媒体に掲載されている求人情報を定期的に取得します。

取得対象は主に以下です。

- HRMOS
- HERP
- リクナビ
- Talentio
- JobCan

取得したデータはCSVとして保存し、後続の案件作成、確認、集計、共有、加工に利用します。

## 頻度・ボリューム

頻度は平日ベースの定期実行です。

| 曜日 | 実行対象 |
| --- | --- |
| 平日毎日 | HRMOS |
| 月曜 | HERP、リクナビ |
| 火曜 | Talentio |
| 水曜 | JobCan |
| 木曜 | Talentio |
| 金曜 | JobCan |

カテゴリは基本的に以下の5カテゴリです。

- WEB
- IN_DS
- CRS
- CRG
- コンサル

リクナビ、HERP、ATS系はいずれもカテゴリ別にCSVが出力されます。

所要時間は媒体や求人件数により変動します。HERPとリクナビは多数のURL・カテゴリを巡回するため長めです。HRMOS、Talentio、JobCanも5カテゴリ分ログインして処理します。

## スケジュールのルール

平日は毎日HRMOSを実行します。

曜日別に以下を追加実行します。

- 月曜: HERP、リクナビ
- 火曜: Talentio
- 水曜: JobCan
- 木曜: Talentio
- 金曜: JobCan

## 実行コマンド

作業ディレクトリは以下です。

```bash
cd /Users/ryuga.uchiyama/git/ats-crawling/ats-processors
```

HRMOSを実行する場合:

```bash
python ats.py --media hrmos
```

Talentioを実行する場合:

```bash
python ats.py --media talentio
```

JobCanを実行する場合:

```bash
python ats.py --media jobcan
```

リクナビを全カテゴリ実行する場合:

```bash
python rikunabi.py
```

リクナビを単一カテゴリだけ実行する場合:

```bash
python rikunabi.py WEB
python rikunabi.py IN_DS
python rikunabi.py CRS
python rikunabi.py CRG
python rikunabi.py コンサル
```

HERPを全カテゴリ実行する場合（約2時間・ブラウザ画面は出ない）:

```bash
cd プログラム本体/herp
python herp.py
```

HERPを単一〜複数カテゴリだけ実行する場合（中断からの再開・1カテゴリの取り直し）:

```bash
python herp.py CRG
python herp.py CRS WEB
HERP_CATEGORIES=IN,コンサル python herp.py   # 環境変数でも指定できる
```

カテゴリ名は `CRG / CRS / IN / WEB / コンサル`（`IN_DS` は `IN` として扱う）。不明な名前は即エラー終了する（黙って全件回さない）。

ブラウザ画面を見たいとき（ログイン失敗の切り分け等）:

```bash
HERP_SHOW_BROWSER=1 python herp.py CRG
```

### HERP の仕組みと落とし穴（2026-09-04 時点）

- **2026/8/5 以降はログイン必須**。ID/PASS は **`プログラム本体/config.yaml` の `login.accounts`**（HRMOS/Talentio/JobCan と同じ）から読む。旧 `herp/password.txt` は残っていれば読むが、新しい環境では不要
- **カテゴリごとにアカウントが異なる**（WEB / IN_DS / CRS / CRG / コンサル）。ログインの起点は中立な `/p/invitations` を使う（カテゴリ1社目の招待URLから入ると別アカウント宛の場合に強制ログアウトされる）
- **企業URLはログイン後の招待一覧 `/p/invitations` から毎回取り直す**。コード内の `HERP_URLS` はフォールバック（招待一覧が取れなかったときだけ使う）。招待の失効・追加に手作業で追従する必要はない
- **カテゴリが終わるたびに CSV を書く**。途中停止しても終わったカテゴリは残る（2026/8/10 に「最後にまとめて書く」作りで2回全損した教訓）
- **検算が入っている**。1カテゴリでも「0件」「案件名が空」「詳細列が無い」「仕事概要の充足率50%未満」なら `🔴 検算NG` を出して `exit 1`。**NG のカテゴリは納品しない**。2026/8/17 に HERP 側の DOM 変更で全列空の CSV を黙って納品した事故の再発防止
- 正常時の目安: CRG 約120件 / CRS 約400件 / IN 約260件 / WEB 約700件 / コンサル 約125件（2026-08-24・09-01 実績）。桁が違ったら疑う
- HERP は UI を頻繁に変える（2026/8/12〜17 に Tailwind 移行でクラス名総入れ替え）。案件名は `<title>` から、詳細テーブルは「td 2つ＝見出し/値」で拾う新旧両対応にしてある

## 期日感

各実行日のうちに、対象日付のCSVが生成されていれば完了です。

朝や日中の確認・利用に間に合わせる運用の場合、深夜から早朝に自動実行されている想定です。

ファイル名に実行日が入るため、対象日付のCSVが生成されているかを確認します。

例:

```text
output/hrmos/hrmos_WEB_item_list_2026-05-29.csv
output/rikunabi/rikunabi_WEB_item_list_20260525.csv
herp/output_herp_jobs/herp-WEB-20260525.csv
```

## 作業の完了状態・条件

作業完了の条件は、対象媒体・対象カテゴリ分のCSVが生成されていることです。

確認ポイント:

- 当日または対象日のファイル名でCSVが作成されている
- ファイルサイズが極端に小さくない
- ヘッダーだけでなくデータ行が入っている
- 実行ログに致命的なエラーがない

主な出力先:

```text
/Users/ryuga.uchiyama/git/ats-crawling/output/hrmos/
/Users/ryuga.uchiyama/git/ats-crawling/output/talentio/
/Users/ryuga.uchiyama/git/ats-crawling/output/jobcan/
/Users/ryuga.uchiyama/git/ats-crawling/output/rikunabi/
/Users/ryuga.uchiyama/git/ats-crawling/herp/output_herp_jobs/
```

`ats-processors/output/` 側にも出力履歴があります。確認時は、実際に当日ファイルが生成されている場所を優先して見ます。

## イレギュラー時の対応

主なイレギュラー:

- CSVが生成されない
- CSVが空、またはヘッダーしかない
- ログインに失敗する
- サイト側のメンテナンス画面やモーダルで止まる
- タイムアウトする
- サイト側の画面構造変更で取得できない

対応順:

1. 該当日の出力CSVがあるか確認する
2. ログがあればエラー内容を確認する
3. 同じコマンドを手動で再実行する
4. ログイン情報や権限が変わっていないか確認する
5. サイト側の画面変更が疑われる場合はエンジニアに相談する

リクナビはブラウザ操作に依存しているため、メンテナンスモーダルや画面構造変更で失敗しやすいです。

HERPは招待一覧を巡回するため、特定URLが無効になっていても他のURLは続行される設計です。検算NGが出たカテゴリだけ `python herp.py <カテゴリ>` で取り直せます。
